4.15 表单校验

注册 / 修改邮箱 / 修改密码共用同一套规则与交互（DESIGN.md §4.15）。空值在失焦、输入阶段不提示，只有点击提交时才提示必填。

时机必须行为视觉结果
失焦（空值）不提示、不报错，必填校验留到提交保持默认样式
失焦（非空）立即执行该输入框的完整规则校验失败：红框 + 13px 红色文案
输入中（已有错误）每次内容变化即时复检一旦合规：立刻移除红框与文案
输入中（密码）逐项实时判断强度规则满足项由灰色 ○ 变绿色 ✓
提交ZIYIT_FV.validateAll([...]) 逐项校验，聚焦第一个非法项空值在此刻提示必填，并阻止请求

4.16 统一按钮加载态

全站所有页面、所有按钮共用一套加载态（DESIGN.md §4.1 / §4.16）。点击后立即拦截重复点击；操作超过 100ms 才显示加载态并禁用，瞬间完成的操作不出现任何闪烁。该次操作触发的 fetch / XHR（含 SSE 流式响应）全部结束后，无论成功或失败都立即恢复。

时机必须行为视觉结果
操作 <100ms 完成不展示加载态，仅静默拦截重复点击按钮外观完全不变，无闪烁
操作持续 ≥100ms第 100ms 进入加载态并禁用转圈 + 加载文案，按钮不可再次点击
加载中拦截重复点击、回车与程序化 click不重复提交，按钮保持加载态
操作成功最后一个请求结束时立即恢复恢复原文案与原宽度，可再次点击
操作失败与成功一致，立即恢复可用恢复原文案，由页面给出失败提示
兜底任何按钮加载超过 120s 强制恢复并告警不会永久卡在加载态
演示（统一脚本自动接管，无需逐个按钮写 loading 代码）：
说明：点击后先静默拦截重复点击；操作超过 100ms 才显示加载态与禁用，因此同步操作、瞬时接口、校验拦截不会有任何闪烁。耗时操作以接口真正结束（含 SSE 流读取完毕）为准立即恢复。特殊场景可用 ZIYIT_BTN.wrap(btn, promise) 手动指定异步任务。
